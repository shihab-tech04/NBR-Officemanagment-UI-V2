Rewrite and standardize all UX writing across the full government office management UI, especially page subtitles, section descriptions, empty states, drawer helper text, modal descriptions, button labels, filter labels, and confirmation messages.

Do not redesign the UI.
Do not change page structure.
Do not rename main navigation items.
Do not remove any page, table, flow, action, or feature.
Only improve the UX writing so the system feels clear, consistent, official, and easy to understand.

Main Goal:
Make every page subtitle and helper text explain what the user can do on that page in simple, useful language.

Writing Style:
- Clear
- Short
- Professional
- Government-office appropriate
- Human and natural
- Action-oriented
- Easy for officers to understand
- No robotic wording
- No marketing language
- No vague descriptions
- No unnecessary long sentences
- No all-caps text

Golden Rules:
- Every subtitle must explain the page purpose.
- Every subtitle should help users understand what they can do next.
- Keep language simple and operational.
- Avoid generic text like “This module is part of the application shell.”
- Avoid repeated subtitles across different pages.
- Avoid vague text like “Manage records and workflows.”
- Do not invent legal or tax rules.
- Do not change official page names.
- Keep page titles short and official.
- Keep subtitles helpful but not long.
- Use sentence case.
- Do not use all-caps labels.
- Use the same tone across the full system.
- Keep wording consistent across buttons, filters, drawers, modals, and empty states.
- Use active voice.
- Use plain English.
- Do not use promotional words.
- Do not use words like seamless, powerful, robust, revolutionary, advanced, leverage, enhance, or optimize.
- Make the UI feel calm, clear, and government-grade.

Page Subtitle Rules:
Each page subtitle should answer one of these:
- What is this page for?
- What can the officer review here?
- What action can the officer take here?
- What kind of records are shown here?

Subtitle Length:
- Ideal: 8–14 words
- Maximum: 18 words
- Keep it one sentence
- No paragraph subtitles

Good Subtitle Examples:
- Review return submissions by circle, type, and status.
- Track pending approvals and recent return activity.
- Review PSR records before approval or correction.
- Manage user access, roles, and account status.
- Create roles and assign permissions by module.
- Review certificate requests and approval status.
- Track litigation cases by type, court, and decision status.

Bad Subtitle Examples:
- This module is part of the application shell.
- Manage all records in one place.
- View and manage data efficiently.
- A powerful dashboard for better decisions.
- Use this page to perform actions.

Empty State Writing Rules:
Empty states must be helpful and action-oriented.

Do not use:
“This module is part of the application shell.”

Use:
- Select an item from the left navigation to continue.
- Choose a record to view details.
- No records found for the selected filters.
- Try changing filters or clearing the search.
- Select a role to view permissions and assigned users.
- Select a report to view filters and results.

Modal Writing Rules:
Modal titles should describe the action:
- Add User
- Edit User
- Create Role
- Edit Role
- Confirm Approval
- Confirm Rejection
- Delete Role
- Apply Filters

Modal descriptions should be short:
- Fill in the details below to create a new user.
- Update the user information and access settings.
- Define the role and select permissions.
- This action will approve the selected record.
- This action cannot be undone.

Confirmation Message Rules:
Use direct but calm language.

Approve:
Title:
Confirm Approval

Message:
Are you sure you want to approve this record?

Reject:
Title:
Confirm Rejection

Message:
Please review the record before rejecting it.

Delete:
Title:
Delete Record

Message:
This action cannot be undone. Please confirm before deleting.

Filter Writing Rules:
Use section labels:
- Filter by Location
- Filter by Status
- Filter by Date
- Filter by Type
- Filter by Officer
- Filter by Assessment Year

Applied Filter Text:
Use:
Now showing filtered results based on following(s)

Better alternative:
Showing results for the selected filters

Use the better alternative if rewriting is allowed.

Accessibility Writing Rules:
- Icon-only buttons must have tooltips.
- Tooltips should be short.
- Error messages must explain the issue.
- Required fields must be clearly marked.
- Validation messages should tell users how to fix the problem.

Validation Examples:
- Enter a valid email address.
- Full name is required.
- Select a role before saving.
- Select at least one permission.
- Date range is required.
- End date cannot be earlier than start date.

Tooltip Examples:
- View details
- Edit record
- Download file
- Print record
- Apply filters
- Clear filters
- Open appearance settings
- Collapse navigation
- Expand navigation
